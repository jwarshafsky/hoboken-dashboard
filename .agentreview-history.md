## Round 1 — 2026-07-30

**Agents:** performance + reliability engineer, QA / failure-modes reviewer,
on-the-move UX reviewer.

**Scope:** whole chain — app source, the launcher's Caddy `/commute/*` route,
the launcher shell, and the Cloud Run proxy path.

**Top findings (this round):**
- [shipped] Launcher posts `{type:'hidden'}` when the tile is swapped out, but the
  page only handled `'shown'` — `document.hidden` follows the TOP-level document
  inside the iframe, so the 15s poll ran forever on the launcher home screen.
  Measured 3 requests per 40s hidden before, 0 after. — perf agent
- [shipped] No fetch path checked `res.ok`. A 5xx with a JSON body rendered as a
  healthy, empty outbound board reading "none soon" — the app asserting no buses
  were coming when it had simply not been told. Fixed in `fetchT` so both
  directions use the error handling they already had. — QA agent
- [shipped] Service worker `activate` deleted every cache on the origin, not just
  its own. Caches are per-origin and on the launcher this SW shares the origin
  with every other tile. Filtered to the `commute-shell-` prefix. — perf agent
- [REJECTED] Serving the app from local disk instead of proxying to GitHub Pages.
  Jeff pre-approved this conditionally; it failed its own gate. Measured gain was
  ~55ms typical / ~103ms worst case, against a ~4.9s cold Cloud Run fetch — about
  2% of a cold open, in exchange for a second copy to keep in sync. The Caddyfile
  comment documenting the original decision was correct and stands. Note the
  premise that prompted this (a 475ms cold proxy hop) was a measurement artifact:
  n=80 real opens from the Caddy access log are p50 61ms / p90 177ms, and 475ms
  was the single worst sample.
- [deferred] Prewarm the Cloud Run commute cache on tile touchstart. Biggest win
  available (~4.4-4.9s → ~0.1s on off-window opens) but adds ~10-20 requests/day;
  needs Jeff's approval on the cost delta even though finding 1 nets it negative.
- [deferred] Exponential backoff on repeated failure (15s→60s). Strictly reduces
  cost, but slows recovery in a way Jeff could notice mid-outage.
- [deferred, CONFLICT] Staleness treatment. QA wants the existing dim + "Times
  from …" applied on the pocket-to-platform path, where a 10-minute-old countdown
  currently shows at full brightness. UX wants the dimming REMOVED — computed
  that at `opacity:.5` metadata contrast falls to 2.84:1, invisible in morning
  sun. Both are right about their own failure mode; the fixes are incompatible.
  Needs a human decision.
- [deferred] All UX findings — every one changes what's on screen: `.mins` has no
  urgency color, scheduled vs live rows are pixel-identical on the inbound board,
  "none soon" conflates no-service with NJT dropout, `#hdrEta` is outside
  `#content` so it escapes both staleness treatments, `.tab` is ~42px (under the
  44px minimum).

**The ONE thing this round:** the launcher tile was polling the proxy forever in
the background because the page ignored the `hidden` message it was already
being sent — now fixed and measured.

**What this round chose NOT to cover** (to inform future rounds): security and
the proxy's auth/CORS posture; cost/quota headroom on Cloud Run; accessibility
beyond contrast and tap-target size; the ferry board specifically; the
`/srv/launcher` shell's own code quality; anything about the wall dashboard or
the other tiles sharing that origin.
